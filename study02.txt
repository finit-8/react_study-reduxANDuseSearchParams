리액트는 SPA방식(하나의 HTML만으로 다양한 컴포넌트를 랜더링)으로 라우팅 방법은 2가지가 있는데, 
그 중 하나는 쿼리스트링(.com/~~~?key=value)을 이용한 방법이고,
다른 하나는 url에 직접 변수를 주는 방법(.com/param/param2/...)이다.
오늘은 url에 직접 변수를 줘서 라우팅 하는 방법을 공부하였다.

(상세페이지 구현은 보통 URL파라미터 방식을 쓰고,
 커서, 조회, 정렬 등 추가적인 부수옵션 줄 때는 보통 쿼리스트링 방식을 쓴다고 한다.)

1. url에 직접 변수를 주는 방법(URL 파라미터 사용하는 방법)은, 
url에 입력된 값을 브라우저가 url인지 변수로 받은 값인지 판단하지 못하므로 
react의 router파일에 등록하여 브라우저한테 알려줘야한다.
	- 부모경로를 선언한 객체 내에 children : [] 배열로 중첩라우팅 
	(배열인 이유는 자식이 하나만 있는게 아니기에 여러 개를 등록하기 위함)
	(중첩라우팅으로 여러 파라미터를 줄 수 있다. ==> ※ ex) 쇼핑몰의 카테고리 제작시 등 유용하게 사용됨)
		children : [
			{
				path : "/hobby/hobbies"			==> x (경로로 인식)
				path : "/hobby/:hobbies"		==> o (변수, 값으로 인식)
				element : <HobbyContainer />
			}
		]
		
2. HobbyContainer.jsx에서
	const {hobbies} = useParams()로 선언하고 return에서 사용.
						↑ URL파라미터를 가져오는 hook함수

3. 어느 페이지에서 상세페이지를 구현
	- PostListContainer.jsx에서 세부페이지로 이동하는 링크를 줘야하고, 
	세부페이지마다 어떤 데이터를 가져올지 구분점을 주기 위해 기본키로 가져온다.
	<Link to={`/posts/read/${post.id}`}>  </Link>

4. 상세페이지 내부 데이터 구현
	- 위 3번은 json데이터값을 가져와서 사용하는데, 실제데이터에는 read라는 프로퍼티는 없다.
		이 말은 API서버(백앤드)에는 실제로 read라는 경로가 없다는 뜻이고,
		리액트의 라우터파일에만 가상의 경로 read를 준 것이라서 단순히 프로퍼티가 아닌 URL상의 경로 역할임.
		따라서, PostReadContainer.jsx에서 데이터를 호출할 때의 주소에 read는 빼고 바로 id를 호출한다.
			fetch(`.../posts/${id}`)
